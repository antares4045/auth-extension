# Браузер формул

## Problem Statement

При разборе отчёта пользователю приходится вручную искать переменные, упомянутые в формулах, затем повторять этот процесс для вложенных формул и отдельно выяснять, из какого источника данных пришёл DP-объект. Маленький popup расширения не подходит для такого исследования: в нём мало места, он закрывается при потере фокуса и не сохраняет контекст переходов.

## Solution

На вкладке «Управление» popup появляется кнопка «Открыть браузер формул». Она открывает поверх текущей страницы отчёта отдельное большое окно расширения. Окно можно перемещать за заголовок, изменять в размере, разворачивать на весь экран, скрывать и открывать повторно без потери истории текущей страницы.

При первом открытии окно загружает `REP.GET_VARIABLES` и `REP.GET_DP_LIST`. Пользователь может выбрать существующую переменную либо ввести произвольную формулу и проверить её через `REP.VALIDATE_FORMULA`. Ссылки на переменные становятся навигационными: выбранная переменная открывается как отдельная страница с формулой, непосредственными зависимостями, рекурсивным деревом и сведениями об источнике. Переходы образуют историю с командами назад и вперёд.

## User Stories

1. Как разработчик отчёта, я хочу открыть браузер формул из вкладки «Управление», чтобы начать анализ в контексте текущего отчёта.
2. Как разработчик отчёта, я хочу видеть инструмент поверх страницы, чтобы не переключаться между вкладками браузера.
3. Как разработчик отчёта, я хочу перемещать окно, чтобы не закрывать важную часть отчёта.
4. Как разработчик отчёта, я хочу менять размер окна и разворачивать его на весь экран, чтобы читать длинные формулы.
5. Как разработчик отчёта, я хочу скрыть и повторно открыть окно без потери истории, чтобы ненадолго вернуться к отчёту.
6. Как разработчик отчёта, я хочу выбрать переменную по имени или идентификатору, чтобы начать анализ с уже существующего объекта.
7. Как разработчик отчёта, я хочу вставить произвольную формулу и проверить её, чтобы исследовать ещё не сохранённое выражение.
8. Как разработчик отчёта, я хочу видеть причину ошибки валидации, чтобы понимать, почему формула не разобрана.
9. Как разработчик отчёта, я хочу открыть любую переменную из формулы, чтобы перейти на следующий уровень зависимости.
10. Как разработчик отчёта, я хочу возвращаться назад и вперёд кнопками и клавишами, чтобы исследовать несколько ветвей без повторного поиска.
11. Как разработчик отчёта, я хочу видеть рекурсивное дерево зависимостей, чтобы оценить структуру формулы целиком.
12. Как разработчик отчёта, я хочу получить полностью подставленную формулу, чтобы видеть вычисление без промежуточных пользовательских переменных.
13. Как разработчик отчёта, я хочу, чтобы циклические ссылки отмечались и не подвешивали интерфейс.
14. Как разработчик отчёта, я хочу видеть тип каждой переменной в знакомом цвете фронта, чтобы быстро отличать Dimension, Attribute и Measure.
15. Как разработчик отчёта, я хочу видеть `dp_id` и название источника для DP-переменной, чтобы быстро найти соответствующий запрос данных.
16. Как разработчик отчёта, я хочу видеть все источники Merge-переменной, чтобы понимать, какие DP-объекты она объединяет.
17. Как разработчик отчёта, я хочу обновить данные вручную, чтобы учесть изменения переменных в открытом отчёте.
18. Как разработчик отчёта, я хочу получить понятное сообщение при отсутствии token/receiver/streamreceiver или ошибке API, чтобы отличить проблему контекста от неверной формулы.
19. Как разработчик расширения, я хочу, чтобы неизвестные будущие `varType` и `type` отображались нейтрально, чтобы развитие формата ответа не ломало браузер формул.
20. Как разработчик отчёта, я хочу видеть явное предупреждение для Merge без источников и повреждённых записей, чтобы не принимать неполные данные за корректные.

## Implementation Decisions

- Окно внедряется content script в закрытый Shadow DOM. Это изолирует стили расширения от стилей открытого сайта.
- Жизненный цикл окна привязан к странице: закрытие скрывает окно, а не уничтожает его состояние. Перезагрузка страницы начинает новую сессию.
- Popup только посылает активной вкладке команду открытия; все API-запросы выполняются из content script, которому доступны token из localStorage и receiver/streamreceiver из sessionStorage страницы.
- `REP.GET_VARIABLES` и `REP.GET_DP_LIST` загружаются параллельно при первом открытии или явном обновлении.
- `REP.VALIDATE_FORMULA` получает `{ formula }`. Успешный ответ используется как корень анализа произвольной формулы.
- Модель индексирует переменные по `id` и извлекает ссылки из `parsedFormula.root`/`tree.root` по узлам `nodeType: "var"` и `varId`.
- Полное раскрытие рекурсивно подставляет формулы пользовательских переменных. DP-листья остаются ссылками на исходные объекты. Циклы и превышение предела глубины явно помечаются.
- Для DP-источника `dp_id` связывается с `dpName` из `REP.GET_DP_LIST`. При недоступности списка остаётся технический `dp_id`.
- Для Merge-переменной отображаются все элементы `merge` с их `dp_id`, `dpObject_id` и найденным `dpName`.
- История содержит как открытые переменные, так и проверенные произвольные формулы. Новый переход после возврата назад удаляет устаревшую ветку «вперёд».
- Горячие клавиши внутри окна: `Alt+←` и `Alt+→` для истории, `Ctrl+Enter` для анализа, `Esc` для скрытия.
- Цветовая схема повторяет SVG старого фронта: Dimension `#1AE3D7 → #0945DF`, Attribute `#19B400 → #09492A`, Measure `#FFC700 → #DF0909`.
- Неизвестные `varType` остаются исследуемыми нетерминальными переменными, а неизвестные визуальные `type` получают нейтральное оформление. Жёсткого исчерпывающего списка серверных типов нет.
- Повреждённые элементы без `id`, `null`-элементы и некорректные DP/Merge-ссылки фильтруются с пользовательским предупреждением; Merge без источников остаётся доступным и явно помечается как неполный.
- Полное раскрытие ограничено одновременно глубиной, числом подстановок и длиной результата, чтобы рекурсивные и экспоненциально разветвлённые формулы не блокировали страницу.

## Testing Decisions

- Единственный программный тестовый шов — публичный API чистой модели браузера формул.
- Тесты проверяют наблюдаемое поведение: порядок прямых зависимостей, рекурсивную подстановку, остановку циклов, разрешение DP-источника и сохранение неизвестных ссылок.
- Отдельные регрессии покрывают прямые и многозвенные циклы, пустой Merge, неизвестный `varType`, повреждённые записи ответа, одноимённые ссылки с разными `varId` и лимиты раскрытия.
- Сетевой слой и DOM не мокируются внутренне. Их интеграция проверяется синтаксической проверкой скриптов и ручным сценарием в загруженном расширении.
- В репозитории до этой функции не было тестовой инфраструктуры; используются встроенные `node:test` и `node:assert`, чтобы не добавлять зависимости.

## Out of Scope

- Редактирование и сохранение переменных отчёта.
- Визуализация вычисленных значений и выполнение формулы на данных.
- Постоянная история между перезагрузками страницы или между вкладками.
- Автоматический поиск текущей выделенной ячейки/переменной внутри React-приложения.
- Изменение исходного фронтенда `tern-universe-2.0-frontend`.

## Further Notes

- В приложенном ответе находится 483 переменные, поэтому UI не должен строить полное рекурсивное дерево до выбора корня.
- Некоторые переменные типа Formula являются техническими формулами ячеек; модель не отбрасывает их, поскольку они могут встретиться в `varId`.
- Спецификация сохранена локально, потому что в репозитории расширения не настроен issue tracker и нет соглашения о triage-метках.
