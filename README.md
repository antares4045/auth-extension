Браузер формул открывается из вкладки «Управление» или настраиваемым хоткеем (`Alt+V` по умолчанию; ссылка на штатную настройку сочетаний находится рядом с кнопкой открытия). В дереве зависимостей доступно полное раскрытие и сворачивание всех ветвей одной кнопкой. Полная формула поддерживает три режима происхождения: без зон, непосредственные переменные и все вложенные уровни. Рядом можно ограничить глубину раскрытия; пустое поле означает отсутствие ограничения по глубине. Выбор режима, глубины и открытость секции синхронизируются через настройки расширения. Галочка «Перепроверять открытые переменные» повторно отправляет открытую переменную и все достижимые из неё зависимости в `REP.VALIDATE_FORMULA`; обновлённые деревья хранятся отдельно от ответа `REP.GET_VARIABLES`, поэтому выключение галочки сразу возвращает исходное представление. При включённой настройке «Подсвечивать скобки» наведение на круглую скобку мягко выделяет её пару и область между ними; выбор тоже синхронизируется. Одинарный клик по переменной показывает карточку, двойной — переходит в неё.

На вкладке «Настройки» можно экспортировать и импортировать резервную копию всего `chrome.storage.sync` вместе с назначенным хоткеем. Файл содержит логины и пароли, поэтому его нужно хранить безопасно. Firefox восстанавливает хоткей автоматически; Chrome/Chromium после импорта показывает сохранённую комбинацию и ссылку на штатную страницу назначения хоткеев.

Вкладка «Очистка» доступна всегда и работает с авторизованным инстансом в текущей вкладке. Она ищет юнивёрсы, соединения и отчёты по серверной маске `REPOS.FIND_OBJECTS` в личном хранилище, общих папках и корзине. Перед удалением показывается полный список: любой объект можно исключить или отдельно переключить между обычным и безвозвратным удалением. Выбранные типы, расположения, маска и режим по умолчанию сохраняются в `chrome.storage.sync`, поэтому входят в общий экспорт и импорт настроек.

Безвозвратный режим передаёт `force=1` и `isFullDelete=1`. Обычный режим передаёт оба признака равными нулю. Перед запуском внимательно проверьте список подтверждения.

## Упаковка CRX

Для первого выпуска создайте signing key и CRX одной командой:

```powershell
.\tools\pack-extension.ps1 -CreateKey
```

По умолчанию ключ создаётся вне репозитория:
`%LOCALAPPDATA%\UniversalAuthInjector\extension.pem`. Сразу сохраните этот файл как
защищённое вложение в менеджере паролей. Потеря ключа означает смену ID расширения;
публикация ключа позволяет постороннему подписывать обновления от вашего имени.

Следующие версии упаковываются той же командой без `-CreateKey`:

```powershell
.\tools\pack-extension.ps1
```

Готовый файл появится в `dist/universal-auth-injector-<version>.crx`. Скрипт сам
находит Яндекс Браузер или Google Chrome; нестандартный путь можно передать через
`-BrowserPath`. Путь к другому экземпляру ключа задаётся через `-KeyPath`, но ключ
внутри репозитория скрипт использовать откажется.

## GitHub Releases

Workflow `Release CRX` создаёт GitHub Release с тегом, совпадающим с версией из
`manifest.json` (например, `v1.2.7`), и прикладывает два файла: исходный `.crx`
и `.crx.zip`. ZIP-обёртка нужна для скачивания через Chrome, который перехватывает
прямую загрузку стороннего CRX как попытку установки. Перед первым запуском:

1. Создайте GitHub Environment с именем `release` и, по возможности, включите
   required reviewer.
2. Преобразуйте сохранённый PEM в Base64 без перевода строк:

   ```powershell
   [Convert]::ToBase64String([IO.File]::ReadAllBytes('C:\secure\extension.pem')) |
     Set-Clipboard
   ```

3. Добавьте результат как environment secret `EXTENSION_PEM_B64`.
4. Увеличьте `version` в `manifest.json`, отправьте изменения в `main`, затем
   откройте **Actions → Release CRX → Run workflow**.

GitHub secret является рабочей копией, а не резервной: прочитать его обратно
невозможно. Резервной копией остаётся PEM в менеджере паролей.
